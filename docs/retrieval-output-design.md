# RAG 交付格式与质量门禁

## 结论

当前目标系统同时接收结构化 QA CSV 和 Markdown，并会自动切分 Markdown。生产默认采用：

- QA：一个知识单元一条 CSV 记录，字段固定为 `Query,Answer,Module`。
- SOP：一个来源小节一份 Markdown；H1 是主题，入口问题紧跟 H1，步骤继续使用原有标题、列表、表格和代码块。
- 主产物每个 QA 只保留一个经过审核的标准问题，不复制相同答案。问法扩写保留在元数据和独立实验产物中，经过离线评测后再决定是否启用。

这里的关键不是 `.csv` 或 `.md` 后缀本身，而是检索原子边界：问题、答案和必要上下文必须进入同一个可检索单元。当前 CSV 导入路径以一条记录为一个 QA 原子，因此比把 QA 写成带 `## 答案` 的 Markdown 更稳；后者可能被标题切分器拆开。

## QA 记录

```csv
"Query","Answer","Module"
"任务 OOM 怎么排查？","先查看……然后执行……","模型训练"
```

约束：

1. `Query` 是一个完整、自然、意图单一的用户问题。
2. `Answer` 自包含，保留条件、步骤顺序、分支、警告、命令、参数、版本和路径。
3. `Module` 只用于过滤或加权，不做硬分库；同一症状仍可召回其他模块的答案。
4. 使用 UTF-8 BOM、`QUOTE_ALL` 和标准 CSV writer，答案中的逗号、引号、换行及代码块不会破坏记录边界。
5. 不用多行重复同一答案来堆问法。重复答案会挤占 top-k 并降低结果多样性。需要扩写时，只使用语义审核通过的等价问题，并单独做对照实验。

## SOP 文档

```markdown
# 任务 OOM 排查

**常见问法（便于检索）：** 任务内存爆了怎么办？｜训练进程为什么被杀？

适用范围、前置条件和结论摘要。

## 步骤

1. ……
2. ……
```

入口问题不能放在 H1 之前，否则结构切分器可能生成“只有问题、没有答案”的孤儿块。上线前必须检查目标系统的分段预览：每个子块应保留 H1/标题路径；如果目标系统不保留父标题，应在切分后给每个子块增加简短的主题上下文，不能简单把所有入口问题重复到每个子块。

## 防丢闭环

流水线必须同时满足以下不变量：

1. 输入文件和引用图片进入内容哈希；图片变化会触发重跑。
2. 视觉转写遇到长度截断时扩大 token 预算重试；再次截断则整篇失败，半截转写不参与抽取。
3. 图片文字参与 section 分类，截图-only 小节不能因正文为空被跳过。
4. 分类响应必须覆盖每个 section id；无效响应默认进入 QA 路径，而不是默认跳过。
5. 每个非 `skip` section 必须对应至少一个结构合格的 QA/SOP 单元，否则整篇失败并保留上一次完整快照。
6. QA 和 SOP 都经过结构门禁、独立的来源对照语义审核、最多一次基于原文的重生成及复审。
7. `results.json` 保存通过和失败候选及审核历史；首跑导出和重放导出使用同一过滤规则。

这些约束保证“不会静默丢失”。正式发布是否要求 100% 覆盖，应由交付门槛决定：若存在失败候选，系统应把它视为待修复缺口，而不是把较少的文件数解释成源文档没有内容。

## 检索评测

不存在对所有语料都最优的格式或 chunk 大小。应建立一组真实问题，至少包含原词、口语改写、缩写、纯现象、跨模块同名问题和无答案问题，并比较：

- `Recall@5`：有依据的正确单元是否进入前 5。
- `MRR@10` 或 `nDCG@10`：正确单元是否排得足够靠前。
- `Precision@5`：前 5 中错误模块、相似但不回答问题的单元占比。
- 无答案误召回率：知识库不包含答案时是否仍返回高分错误结果。
- 完整性通过率：被召回内容是否包含全部必要步骤、条件和例外。

优先实验顺序：标准 QA 基线；加入模块/标题上下文；向量与 BM25 混合；rerank；最后才是经过审核的问法扩写。一次只改变一个变量，不能用“生成回答看起来不错”代替检索指标。

## 研究依据

- Microsoft Advanced RAG 指南建议为每个 chunk 创建它能回答的示例问题，以改善 query 与 chunk 的对齐，并建议按使用场景评测 chunk 策略：<https://learn.microsoft.com/en-us/azure/developer/ai/advanced-retrieval-augmented-generation>
- Anthropic Contextual Retrieval 通过给 chunk 添加文档级上下文降低检索失败率；其公开实验中 contextual embeddings + BM25 将 top-20 失败率从 5.7% 降到 2.9%，再加 rerank 降到 1.9%。这些数字属于其数据集，不应直接外推：<https://www.anthropic.com/news/contextual-retrieval>
- Document Expansion by Query Prediction 说明把文档可能回答的问题用于索引扩展可以改善检索，但仍需与 reranker 和实际数据共同评测：<https://arxiv.org/abs/1904.08375>
- Dense X Retrieval 的实验表明检索单元粒度会显著影响检索和下游 QA，细粒度、自包含的事实单元优于粗粒度 passage 的情形很多：<https://arxiv.org/abs/2312.06648>
- Google Document AI Layout Parser 强调按标题、列表、表格等布局实体生成上下文一致的 chunk，以降低噪声：<https://cloud.google.com/vertex-ai/generative-ai/docs/rag-engine/layout-parser-integration>
