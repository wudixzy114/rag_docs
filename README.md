# 诊断知识库文档处理流水线（ragkb）

把零散的 Markdown / Word / PDF 文档，规整成可直接灌入向量库的高质量「知识单元」：

- **QA 单元** → `qa_pairs.csv`（`Query, Answer, Module` 三列）
- **SOP 单元** → `sop/*.md`（清洗后的流程/说明文档 + 入口问法）

流水线自动完成：解析 → **用大模型视觉读原图**（不信任预置 OCR）→ 分类 → 抽取 → 结构门禁 → 语义审核 → 跨文档聚合去重 → 导出。全程可观测、可断点续跑。

## 1. 环境准备

依赖用 [uv](https://github.com/astral-sh/uv) 管理。

```bash
# 安装依赖（在仓库根目录）
uv sync

# 配置网关凭证：复制模板，填入真实值
cp .env.example .env
# 然后编辑 .env，至少填 JD_LLM_API_KEY 和 JD_LLM_BASE_URL
```

`.env` 里的关键项见 [第 6 节](#6-配置项)。`.env` 已被 gitignore，不会入库。

> 之后所有命令都用 `uv run ragkb ...`，或先 `source .venv/bin/activate` 再直接 `ragkb ...`。下文统一写 `ragkb`。

## 2. 怎么放输入文件

**这是使用本仓库的第一步，也是最重要的一步。**

所有待处理文档放在仓库根目录的 **`input/`** 下。流水线会**递归**扫描 `input/`，自动发现所有支持的文档，无需登记清单。

### 支持的文档格式

`.md` `.markdown` `.txt` `.html` `.htm` `.docx` `.pdf`
（图片格式：`.png` `.jpg` `.jpeg` `.gif` `.webp`）

### 推荐的目录形式（一文档一目录 + images 子目录）

每篇文档单独一个文件夹，正文命名为 **`原始文档.md`**，配图放在同目录的 **`images/`** 子目录里：

```
input/
├── 基本概念/
│   └── 原始文档.md                    # 无图纯文本也可以
├── 创建或加入工作空间/
│   ├── 原始文档.md
│   └── images/
│       ├── img-01.png
│       └── img-02.png
└── 产品动态/
    └── 2025产品动态/
        └── V2.5.0-2025年12月/
            ├── 原始文档.md            # 支持任意深度嵌套
            └── images/
                └── img-01.png
```

**要点：**

1. **主题名（Module）= 文档所在文件夹名。**
   - 若文件叫 `原始文档.md` 或 `index.*`，主题名取**父文件夹名**（如上例 `基本概念`、`V2.5.0-2025年12月`）。
   - 否则主题名是 `父文件夹__文件名`。
   - 主题名会作为 `Module` 列写进产物，是向量库的**软标签**（用于按模块过滤/加权，但检索不硬分区）。所以**文件夹起个有意义的名字**。

2. **图片这样引用**：在 `原始文档.md` 里用相对路径 `![](images/img-01.png)`。流水线会找到 `images/` 下的原图，**用大模型视觉能力忠实转写**（比预置 OCR 准）。

3. **目录可任意嵌套**（如 `产品动态/2025产品动态/V2.5.0.../`），扫描是递归的。

4. **隐藏文件/目录会被跳过**（以 `.` 开头的，如 `.DS_Store`、`.git`）。macOS 的 `__MACOSX/` 请删掉。

5. 不强制要求一文档一目录——单个 `.md`/`.docx`/`.pdf` 直接丢 `input/` 也能跑，只是主题名会退化成文件名，且无法关联图片。**批量素材建议用上面的目录形式。**

> `input/` 已被 gitignore，你的语料不会误提交进仓库。

## 3. 怎么跑起来

### 最简单：跑全部

```bash
ragkb run
```

这会处理 `input/` 下所有文档，完成后自动导出产物到 `output/`。终端会实时打印每篇文档的状态。

### 常用变体

```bash
# 只跑指定主题（可多次 --only），调试单篇时很有用
ragkb run --only 基本概念 --only 创建或加入工作空间

# 强制重跑（忽略"已完成"的幂等跳过；但不会覆盖 pinned 的文档）
ragkb run --force

# 只处理、暂不导出
ragkb run --no-export

# 从上一次运行的 results.json 重新导出产物（不重新调用模型）
ragkb export
```

### 用网页仪表盘跑（推荐，可视化 + 可中途跟踪）

```bash
ragkb serve            # 默认 http://127.0.0.1:8000
ragkb serve --port 8137
```

打开浏览器即可看到：总进度条、每篇文档的流水线阶段、实时事件、调度器并发、QA/SOP/失败结果。页面上有「运行全部」「重试」「导出」「固定(pin)」按钮，也能直接在网页里触发运行。详见 [第 4 节](#4-怎么中途跟踪进度)。

## 4. 怎么中途跟踪进度

内容多时一次运行可能要几十分钟，中途跟踪有**两种方式**，两者共享同一份磁盘事件流（`output/events.jsonl`），**无论你用 CLI 还是网页触发运行，都能被跟踪到**。

### 方式 A：命令行日志（适合无人值守 / 让 AI 盯）

`ragkb run` 会把进度打到 stdout。后台运行并跟踪日志：

```bash
# 后台运行，日志写文件
nohup ragkb run > output/run.log 2>&1 &

# 实时看进度
tail -f output/run.log
```

**日志里怎么读关键信号：**

| 日志片段 | 含义 | 要不要管 |
|---|---|---|
| `[RUNNING ] 主题名` / `[DONE ]` / `[FAILED ]` | 文档级状态 | 正常 |
| `=== run started/done/exported ===` | 整轮运行的起止 | 正常 |
| `[FALLBACK] section ... 回退为 SOP` | 某段判为 QA 但抽不出，自动回退成 SOP（非静默，会明确打出来） | 正常，留意即可 |
| `429 ... code:2003 请求次数超过模型限流阈值` | **限流**，客户端自动退避重试 | **不用管**，会自动恢复 |
| `gateway congestion window reduced` | 自适应并发在降速避让限流 | 不用管 |
| `vision transcription truncated ... retrying` | 大图转写超长，自动加大 token 重试 | 不用管 |
| `429 ... code:2001 模型配额已用尽` | **配额耗尽**，自动切下一个 fallback 模型 | 留意；若全部模型耗尽会停下，见 [第 7 节](#7-断点续跑与幂等) |
| `✗ 主题名: ...` / `Traceback` | 某篇文档失败 | **要看**，但只影响该篇，不影响其他文档 |

> **让 AI 中途跟踪**：让它 `tail -f output/run.log`，并按上表区分「瞬时限流(2003，自动恢复，不用管)」和「配额耗尽(2001) / 文档失败(✗) / Traceback（要看）」。关键原则：`2003` 是噪音，`2001` 和 `✗` 才是信号。

### 方式 B：网页仪表盘（适合人看，可视化）

```bash
ragkb serve --port 8137
```

- **总进度条**：绿=完成 / 蓝=运行中 / 红=失败，运行中的文档按阶段加权计入。
- **调度器并发**：实时显示当前并发调用数、自适应窗口、慢启动/拥塞避让相位——可观察吞吐。
- **实时事件面板**：逐条事件流（回退、错误等；高频的并发心跳不刷屏）。
- **文档队列 + 流水线视图**：点某篇文档看它 7 个阶段（解析→图片→分类→抽取→校验→重生成→审核）的进度。

仪表盘从磁盘事件流读取，**即使运行是在另一个终端用 `ragkb run` 启动的，网页也能实时反映**。

## 5. 产物说明

运行/导出后，产物在 `output/`：

| 文件/目录 | 内容 |
|---|---|
| `qa_pairs.csv` | 主产物。`Query, Answer, Module` 三列，UTF-8-BOM + 全引号，CJK/逗号/换行安全。 |
| `sop/*.md` | 清洗后的流程/说明文档，文件名 `模块__章节号.md`，正文含「常见问法」入口问句。 |
| `by_module/<模块>/` | 按模块分区的同款 CSV + sop，便于逐模块灌库。 |
| `metadata.jsonl` | 溯源侧车（unit_id、模块、问法变体、来源章节/图片等），不进 CSV。 |
| `知识库上传包.zip` | 打包好的上传包（CSV + sop/ + by_module/ + metadata.jsonl），UTF-8 文件名，无 `.DS_Store`。 |
| `results.json` | 本轮抽取的完整结果快照，`ragkb export` 可据此重放导出。 |
| `manifest.json` | 每篇文档的处理状态（用于幂等/断点续跑/pin）。 |
| `events.jsonl` | 事件流（供仪表盘/日志跟踪，可安全删除）。 |
| `.cache/` | 视觉/抽取/SOP 的内容寻址缓存（断点续跑的关键，**别删**）。 |

> 只有**通过语义审核**的单元才会进 CSV 和上传包；审核失败的会留在 `results.json` 里标记 `failed_review`，不会污染产物。

## 6. 配置项

在 `.env` 里配置（详见 `.env.example`）。分两组：

### 网关凭证（`JD_LLM_*`）

| 变量 | 说明 |
|---|---|
| `JD_LLM_API_KEY` | **必填**。网关 API Key。 |
| `JD_LLM_BASE_URL` | 网关地址，OpenAI 兼容根路径（如 `http://llm-gw.jd.local/v1`）。 |
| `XIAOSHU_MODEL` | 主模型 id。 |
| `JD_LLM_FALLBACK_MODELS` | 逗号分隔的 fallback 链；某模型配额耗尽时按序切换。 |
| `JD_LLM_TASK_MODELS` | 可选。按任务路由模型的 JSON，如 `{"classify":"...","review":"..."}`。 |
| `JD_LLM_VISION_MODELS` | 可选。**仅多模态**模型（读图用）；绝不能放纯文本模型。 |
| `JD_LLM_SIMPLE_MODELS` | 可选。简单任务（问法扩写）的快/省链。 |
| `JD_LLM_TIMEOUT` / `JD_LLM_MAX_RETRIES` | 单请求超时秒数 / 瞬时错误重试次数。 |

网关同时支持三种协议（OpenAI `/chat/completions`、Anthropic `/anthropic/v1/messages`、Gemini 原生 `/v1/responses`），客户端按模型名自动路由，无需手工指定。

### 流水线开关（`RAGKB_*`）

| 变量 | 默认 | 说明 |
|---|---|---|
| `RAGKB_MAX_WORKERS` | 4 | 文档并发数。也是全局并发上限（网关有限流，调太高只会增加重试）。 |
| `RAGKB_SEMANTIC_GATE_POLICY` | `fail_closed` | 审核无法定论时：`fail_closed`=丢弃（安全，绝不发布未审内容）/ `keep`=保留并标记待人工复核。 |
| `RAGKB_ENABLE_PARAPHRASES` | false | 是否额外生成问法扩写（实验性，主产物默认忠于原文）。 |

## 7. 断点续跑与幂等

流水线设计为**可随时中断、随时续跑**，尤其是内容多、可能中途配额耗尽的场景：

- **内容寻址缓存**（`output/.cache/`）：每张图的视觉转写、每段的抽取结果，一旦成功就落盘。**重跑时已完成的部分秒过**，只处理没做完的。
- **幂等跳过**（`output/manifest.json`）：已完成且源文件未变、流水线版本未变的文档，重跑自动跳过（`SKIPPED`）。改了源文件或 prompt 版本会自动重算。
- **配额耗尽时的行为**：某模型配额尽（`code:2001`）自动切 fallback；若**所有**模型都耗尽，当前调用失败但**不丢已完成的工作**——`results.json`、缓存、manifest 都已存盘。等配额恢复后，**直接再跑一次同样的命令**即可从断点继续。
- **pin（固定）**：在仪表盘里 pin 一篇文档后，重跑**绝不覆盖**它——已人工确认的产出不会被后续运行改动。

> 因此：**中途因限额停了，不用慌。已完成的都在。恢复后重跑同一命令即可续上。**

## 8. 常见问题

**Q：文档放进去了，`ragkb run` 却没处理？**
- 检查扩展名是否在支持列表里；
- 检查是否被隐藏路径跳过（`.` 开头的目录/文件）；
- 若是「已完成」被幂等跳过（`SKIPPED`），用 `ragkb run --force` 强制重跑。

**Q：日志里一堆 429，是不是坏了？**
- 看 code：`2003 请求次数超过模型限流阈值` 是**瞬时限流**，自动重试，不用管；`2001 模型配额已用尽`才是配额问题。

**Q：某篇文档 `✗ 失败` 了，会影响别的吗？**
- 不会。文档间隔离，一篇失败不影响其他篇，也不会写进产物。失败不入缓存，重跑会自动重试该篇。

**Q：怎么只重导出、不重新烧钱调用模型？**
- `ragkb export`，从上一轮 `results.json` 重放导出。

**Q：网页仪表盘看不到 CLI 运行的进度？**
- 确认两者用的是同一个 `output/` 目录（同一仓库根目录启动即可）。事件走磁盘 `events.jsonl`，跨进程可见。
